本番と分離したネットワーク、コンソール経路、1.4／1.5の対象ビルドを用意します。次の表を実測したビルド名と結果で更新してください。

|---|---|---|

## 受入シナリオ

1. bootstrap手順で管理接続とreload復旧を構成する。現在の実機設定をconfig.bootへ取り込み、秘密値がある場合は独自のVault鍵で分離する。
2. plan前後の稼働設定・保存設定を比較し、両方が不変であることを確認する。候補セッションと一時ファイルが残らないことも確認する。
3. 非管理インターフェースと静的ルートを追加・変更・削除し、Gitにない設定も削除されることを確認する。
4. 同じapplyを再実行し、commitとsaveが発生せず`changed: false`になることを確認する。
5. 管理IP、SSHポート、投入ユーザー、鍵の変更をそれぞれ試し、commit前に拒否されることを確認する。
6. 系列違い、不正な接続IP、閉じ忘れ、欠落した秘密変数、秘密値の引用符／制御文字、無効鍵、未登録ホスト鍵で安全に失敗することを確認する。ネイティブ設定内の不正IP・未知のコマンドは実機のload／commitで拒否されることを確認する。
7. 未保存の変更、既存の候補セッション、未確定commit、2つの同時実行で投入が停止することを確認する。
8. 仮適用後に管理接続を遮断、ping宛先を到達不能化、コントローラーを停止するケースを個別に試す。confirm／saveが行われず、期限後に**再起動なし**で投入前へ復旧することをコンソールで確認する。
9. 確定後のsaveを失敗させ、`applied_not_saved`になり、save.ymlで保存のみを復旧できることを確認する。
10. 正常投入後に再起動し、設定と通信が維持されることを確認する。
11. Ansibleログ、result.json、CI出力に秘密情報が出ないこと、成果物の0600／0700権限を確認する。

ConfigTreeの意味比較、CLI応答・エラー検知、候補セッションのPID検出、reload能力判定を対象ビルドで必ず確認してください。ビルド変更時は全シナリオを再実施します。単体テストでSSHや復旧タイマーの実際の動作は保証できません。
