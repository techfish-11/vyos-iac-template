# 失敗時の復旧

## まず表示を見る

まず、画面の「次の操作」に従います。詳細は結果に表示された保存先の`result.json`にあります。既定は`~/.local/state/vyos-iac/<機器>/<実行ID>/`です。接続タイムアウトでも、実機がコマンドを実行済みの場合があります。

| 状態 | 対応 |
|---|---|
| `unchanged` | commit前に停止。候補セッションの終了と一時ファイルの削除を確認する |
| `commit_outcome_unknown` | commit結果が不明。confirm／saveせず、期限経過後に実機状態を確認する |
| `awaiting_rollback` | 仮適用後に検証失敗。confirm／saveせず、10分など指定期限の復旧を待つ |
| `confirm_outcome_unknown` | confirmの結果が不明。コンソールでタイマーと稼働・保存設定を確認する |
| `applied_not_saved` | confirm済みで保存未完了。稼働設定をレビューし、保存復旧を実行する |
| `saved`＋cleanup失敗 | 設定は保存済み。セッション・一時ファイルの後処理を行う |

自動復旧はSSH接続が切れても機器側のタイマーで動作します。コントローラーは復旧完了を保証しません。コンソールまたはSSHで稼働設定が投入前へ戻ったこととタイマーが停止したことを確認してから再実行してください。実行前に未確定commitがある場合は投入を拒否します。

## 保存のみを復旧する

`applied_not_saved`では、Gitの設定と実機の稼働設定が一致していることをレビューし、次を実行します。

```bash
./vyos save router01
```

この操作はload／commit／confirmを行いません。未確定タイマーがないこと、管理設定の維持、候補設定と稼働設定の一致、通信、SSH再接続を検証し、saveと保存結果の確認を行います。任意の未保存設定を無条件に保存する操作ではありません。初版では比較対象に省略したデフォルト値があると一致を拒否する場合があります。その場合は実機設定を確認し、コンソールでレビュー済みの設定を保存してください。

## バックアップから戻す

接続が失われた場合はコンソールを使用します。対象機器の`running.config.boot`または`saved.config.boot`を確認し、権限を制限した一時ファイルとして実機へ転送します。

```text
configure
load /config/recovery.config.boot
compare
commit-confirm 10
# 管理接続・必要な通信・設定内容を確認する。
confirm
save
exit
```

稼働設定のバックアップと保存設定のバックアップは別物です。どちらを復旧するか変更記録で確認してください。復旧後は一時ファイルを削除し、Gitと実機の設定を再び一致させます。未確認の状態で`confirm`や`save`を実行しないでください。

## 後片付けに失敗した場合

設定の状態は`state`で先に確認します。`saved`でも後片付けが失敗していれば操作全体は失敗として報告します。コンソールで自分の設定セッションと一時ファイルの所有者を確認し、他の作業を止めずに片付けます。

- 候補設定だけが残った自分のセッションは、`exit discard`で破棄します。
- 実機の`/tmp/vyos-iac-<実行ごとのID>/`は、一時設定と構成取得用ファイルの置き場です。進行中の投入がないこと・所有者・内容を確認し、該当するディレクトリだけを削除します。
- `/config/.vyos-iac.lock`は残っていて正常です。排他はプロセスのflockで保持します。ロックファイルを削除して競合を回避しないでください。

コントローラーが強制終了した場合は最終記録がないことがあります。過去の成功記録から今回の成功を推測せず、実機のタイマー・稼働設定・保存設定を確認します。
